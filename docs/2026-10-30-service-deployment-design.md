# 会议服务发布与部署设计

目标是在保留现有 HTTPS、SQLite 持久化与设备协议的前提下，提供可复现的容器构建、自动检查、版本化镜像发布和单机部署流程。参考 agent-hub 的 Dockerfile、Compose 快速启动和 GitHub Actions 发布方式；本服务不依赖 MySQL。

- 使用固定 Node 22 基础镜像与 npm 锁文件构建镜像，以非 root 用户运行，排除录音、凭据、测试和本地数据。应用进程接收 SIGTERM，预留关闭排水时间。
- Compose 默认仅绑定宿主机回环地址，持久化数据库目录，挂载只读 TLS 证书及私钥，凭据由部署者在本机提供，不写入镜像或仓库。设备访问需要部署者明确配置可达地址、可信证书及网络访问控制。
- CI 在 Node 22 上执行完整测试并构建镜像；版本标签触发镜像发布，使用不可变版本标签，不自动部署或推送 latest。镜像仓库、权限和发布凭据在工作流中明确配置。
- 部署说明覆盖安装、证书与凭据、启动、状态检查、升级、回滚、备份恢复及删除边界。升级前备份，保证单实例和最新安全状态；不宣称设备联调或生产安全审计已完成。
- 验证包括 Compose 配置、镜像构建、容器启动及 HTTPS 健康检查、持久化与重启；如 Docker daemon 或镜像仓库不可用，明确记录未验证项。

## 持久化边界

当前实现的音频上传块是 SQLite `chunks.data` BLOB；确认清单、任务、转写、纪要及批次检查点也存于同一数据库，不存在另一个持久音频目录。容器应将 `MEETING_DATA_DIR=/var/lib/meeting` 整个目录挂载到持久卷，包含数据库、WAL、SHM 与锁文件；不得只挂载数据库单文件。容器用户必须拥有该目录并可读写（0700），TLS 私钥以只读挂载提供并确保该用户可读；凭据和证书由部署方独立保管。未来如引入外部文件，须先扩展一致性方案，不能沿用此假设。

## 快照、恢复与回滚

使用 [备份与恢复说明](../server/BACKUP.md) 的 SQLite 一致快照，备份包含音频块及任务数据；同时独立保管同实例最新安全状态。恢复前停止服务和所有工作器，直至切换完成；保全最新数据库及 WAL，使用恢复工具校验实例身份、数据完整性并应用删除墓碑、撤销记录和最新凭据。旧备份缺少随后已确认的音频或结果时工具必须失败，不得上线；需要更完整的备份或当前库。缺少可信的最新安全状态时同样阻止上线并人工核对；实例 ID 本身不能证明状态最新。备份之后已确认的会议不能因为选择旧恢复点而静默丢失；未确认上传按恢复工具规则从安全状态复制。备份与安全状态本身需要加密、异地保管和明确保留期，当前工具不提供自动多机复制或物理擦除保证。

每次发布应提供旧版、新版、数据库 schema 和设备协议的兼容矩阵与迁移说明，并在副本上测试升级和回滚。只有明确证明旧镜像可安全读取升级后数据库且协议兼容时才允许原地回滚；否则停止写入并走上述经过验证的恢复流程。无法证明兼容、无法获得完整安全状态或恢复校验失败时保持离线并人工处理。升级前做备份，失败后保全当前库及 WAL，不覆盖唯一副本。

## 发布追溯与验收

版本 Git 标签由受限发布身份创建并保护，发布任务核对标签指向的提交和对应测试结果；发布前检查仓库是否已有该版本，发现已存在即失败。镜像仓库须配置版本标签不可变及受限写权限；若仓库无法保证不可变，不宣称标签不可变。记录提交 SHA、CI 测试运行和推送后的镜像 digest，部署与回滚均固定 digest；发布不可依赖标签名作为唯一身份。

验收包括删除并重建容器后读取已确认音频、恢复未完成上传块；测试升级、旧镜像兼容与回滚；在备份后新增已确认上传、撤销凭据、删除会议，验证恢复不会复活删除或撤销，也不会静默丢失已确认音频。覆盖缺失最新安全状态、备份缺块及迁移失败的拒绝上线。上述均为待执行要求，当前 Docker daemon 不可用，尚无容器验收证据。
