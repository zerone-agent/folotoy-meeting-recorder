# 会议录音卡实施计划（工作草稿）

**目标：** 完成设备离线录音、会后可靠上传、服务端转写与纪要的端到端流程。

**设计依据：** [总体设计](../specs/2026-10-29-meeting-recorder-design.md)；[服务端专项设计](../../2026-10-30-agent-runtime-service-design.md)。

**技术基线：** ESP32-C3 / ESP-IDF 5.5.3；Node.js 22+ / TypeScript / agent-runtime；StepFun `stepaudio-2.5-asr` 和 `step-3.7-flash`。

## 顺序及验收

1. **隔离源码和依赖**：固定官方参考固件及 agent-runtime 版本，保留现有研究、未提交内容与测试音频；确定独立实现目录及构建环境。验证源码标识、干净构建和现有测试，记录不可运行的检查。
2. **服务端存储和协议**：实现设备身份授权、会议分块写入、校验、最终清单、持久任务及状态。测试重复/乱序块、跨设备访问、确认丢失、文件发布和数据库提交各阶段崩溃；只有音频和任务都可恢复才确认。
3. **工作器和删除**：实现租约代次及令牌、崩溃恢复、删除墓碑与任务取消。注入旧工作器晚返回、重复接管、处理各阶段删除和重启，验证不能复活或覆盖结果。
4. **ASR 和纪要**：接入 SSE 的完整结果语义与失败重试；调用纪要模型，保存不可变转写版本及可校验证据范围。以模拟接口测试断流和重试，另以用户授权的样本验证真实提供商；不把模拟结果作为端到端通过。
5. **配网和认证**：落实管理员认证、BLE 配对、设备凭据、TLS 证书、可信初始时间与离线撤销待办；测试越权、错误时间、失效凭据及重启恢复。保留策略须明示并验证。
6. **设备录音与上传**：实现 30 分钟上限、Opus 存储、空间预留、断电恢复、录音优先、会后 Wi-Fi 上传及确认后清理。特别验证存满后仍可保存和删除、上传并发删除、断网与重启；不得自动格式化已有数据。
7. **端到端验收**：在实机与本机服务上验证离线录音、恢复网络、完整接收、ASR、纪要与状态展示，分别记录构建、模拟测试、真实接口和实机结果。刷机前再次确认镜像和现有设备数据。

本计划尚需细化文件接口、管理身份和 BLE 安全机制、数据保留策略、测试命令与分阶段交付；不能将其视为已完成的可执行计划。
