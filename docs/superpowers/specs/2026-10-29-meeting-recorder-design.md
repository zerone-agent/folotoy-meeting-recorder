# AI Passport 会议录音卡初版设计（待评审）

## 目标和范围

此前讨论的 60 分钟是探索目标；用户随后明确将初版单次上限调整为 30 分钟，旧调研中 60 分钟测算仅供参考。单次会议录音上限为 30 分钟；达到上限时自动停止、保存已录音频并清晰提示。实际可用空间不足时可能提前停止，必须提示原因。设备通过实体按键开始、结束会议录音；录音期间保存在设备，断网仍可继续，结束后联网自动上传。服务端接收完整音频，自动 ASR、生成会议纪要并展示处理状态。保留原始音频直至服务端确认持久化。初版不做实时上传、多人说话人识别、手机中转或云端正式部署。

## 方案比较

- 设备通过 Wi-Fi 直连、录音结束后上传（用户选择）：操作简单，离线可用，需设备配网和可靠上传；单次最长受设备存储限制。
- 边录边上传：在线时缓解存储压力，但并发与失败恢复复杂，本次不采用。
- 手机或电脑中转：可减轻设备联网工作，但依赖中转终端，本次不采用。

## 设备与交互（建议，待确认）

基于官方 ESP-IDF 参考基线，复用板级音频及社区 Opus/LittleFS 的适用部分，审核其许可和实现，不沿用第三方兼容协议。短按 OK 开始；录音中长按 OK 结束并保存；上/下查看状态和待上传列表。屏幕显示录音、剩余空间/预计时长、网络、等待上传、上传进度与错误；避免把未校准时间显示成真实日期。按键回调不阻塞，音频、存储、网络分属任务。

每次会议有稳定唯一 ID；录音以可恢复的分段及元数据持久化。预留足够文件系统空间用于提交元数据和清理，不静默覆盖已有音频；空间不足时停止采集、保存已有部分并明确提示。达到 30 分钟上限时自动结束并保存，标记为达到时长上限，提示用户；这不表示实际会议已结束。检查写入、同步、关闭和删除结果；挂载失败不得自动格式化已有录音。断电恢复标记为中断会议，不自动伪装为完整会议，允许用户结束并上传已保存部分。容量耗尽或达到 30 分钟上限均标记为截断；服务端和纪要须显著标明不完整，不得显示为完整会议。实际同步周期、最大损失窗口和存储格式需原型与故障注入确定。

**录音优先与上传状态。** 设备仅在无录音时上传。上传中短按开始录音时，立即停止发起新块，取消或有界等待当前请求，不等待整段上传；采集任务优先启动，未取得服务端确认的块保持待重试，画面显示录音中、上传暂停。实现须保证按键到实际采集的延迟有明确目标并在设备上测量，不以队列已接收代替采集开始。录音停止并完成持久化后恢复待上传队列；反复切换、网络请求取消或重启均从持久化状态恢复，不能后台继续上传干扰录音，不能丢失或重复处理块。资源不足无法安全启动时明确提示失败，不显示正在录音。实际延迟阈值待硬件实测后确定。

保存完成后，设备自动连接已配置 Wi-Fi 并上传整个会议的已保存内容；传输可按块进行、断点重试，但录音期间不上传。设备和服务端使用会议 ID、块序号、长度、哈希及幂等确认；上传过程再次断网不删除设备音频。完整性确认包括块数、总长度与整体校验，服务端在音频、元数据和待处理任务均可跨服务重启恢复后返回最终确认，设备自动删除对应的本地音频以释放空间；上传失败、确认丢失或校验失败时必须保留并重试。清理过程断电后必须能恢复为已确认或待重试状态，不能误删未确认数据。服务端保留期限待确定。

**首次配置和认证（本地验证默认方案，待评审）。** 本机提供一个配套配置工具，通过 BLE 连接设备；设备屏幕显示一次性配对码，用户在工具中输入，完成设备身份确认和加密配置通道后，写入 Wi-Fi、服务端地址、信任锚及设备凭据并同步时钟。服务端签发唯一设备凭据，设备到服务端使用 HTTPS，验证服务端证书和主机名；本地验证使用具有对应主机名的本地 CA，CA 指纹需在可信本机配置流程中核验，不关闭证书验证。凭据存设备持久存储，服务端保存可验证凭据的安全表示，日志不记录秘密。具体安全配对实现、证书签发与本地网络限制须在实施计划中选定并实测，不把自签证书或配对码本身视作已验证安全。凭据重置由设备上明确确认操作触发，删除设备保存的网络与设备凭据并重新配对；录音和上传/删除待办不随重置删除。撤销旧凭据由本机配套工具以**独立于设备凭据的服务端管理身份**执行；管理身份通过服务端本地管理员认证取得，不能仅凭设备 ID、BLE 配对码或新设备凭据撤销旧凭据。具体管理身份的签发、保护与权限边界须在实施前确定并验证。设备在删除旧凭据前，将旧凭据的非秘密标识、设备 ID、重置事件 ID 和撤销待办持久化，不保留旧凭据本身；配套工具经用户确认读取并保存待办，以同一事件 ID 幂等重试撤销，只有服务端持久化撤销并回执后才将待办标记完成并同步设备。设备、工具或服务端重启不得丢失待办；重配后的设备凭据不能自行代替管理授权。服务端不可达或管理身份不可用时，设备和工具明确显示“旧凭据尚未撤销，可能仍可访问”，不宣称远端已撤销；在此窗口旧凭据可能仍有效，配套工具联网后持续提示并可重试，管理员可在服务端独立撤销。服务端确认撤销后旧凭据立即拒绝，记录审计事件；新配对和撤销旧凭据的状态分别显示。录音结束后通过 Wi-Fi 直传，不依赖配套工具持续在场；蓝牙音频导出不纳入初版。设备屏幕显示配网、连接失败、上传与重试状态。未校时录音保留设备生成的单调标识，时间标记为未确认；联网后从可信服务校时，不把上传时间当作录音时间。

## 空间不足和手动删除（本地验证默认方案，待评审）

空间不足时不覆盖未上传录音；列表显示待上传、失败和占用。联网恢复后可手动重试。初版提供设备端选择单条录音并长按触发删除，再按照下文所述的本地已知确认状态显示对应风险提示，由用户二次明确确认；取消不删除。删除时检查文件、索引及持久化结果，删除成功后重新计算可用空间并回读；失败保留条目、显示错误，不允许仅从内存列表消失。服务不可用时这是腾出空间的明确有损选择，未确认不得自动删除。初版无本地导出功能，用户若需保留只能先恢复服务并上传；不能宣称有备用导出能力。

### 删除与上传并发规则

设备按会议 ID 串行化上传、最终确认、自动清理和手动删除；二次确认后先将 `删除中` 意图及操作 ID 持久化，再阻止该会议重新入队，停止发起新请求，并取消或等待在途请求退出，确保没有本地读取者后才清理文件。删除意图与自动确认清理使用同一状态机及持久化顺序；重启先恢复删除意图和继续清理，直到验证文件与索引已删除并回读空间，失败保留可见的删除失败状态和重试入口。晚到的块响应或最终确认不得使删除中会议恢复上传或重新生成本地文件；网络请求取消不能假定服务端没有收到它。重复删除、取消、确认及重启必须幂等。

手动删除指删除**设备本地副本**，不等于撤销服务器数据。用户确认前依本地已知状态提示：尚未确认时“服务器可能已收到部分或全部数据；删除后设备无法继续上传，已上传数据可能仍在服务器”；已确认时“服务器已确认保存，删除设备副本不会删除服务器记录”；状态不确定时不宣称未上传或已删除服务器副本。若服务端尚未完成确认，本机异步发送幂等取消请求：服务端以会议 ID 和持久化终态串行化取消与最终提交；取消先提交则拒绝后续块/结束请求，按服务端保留策略清理暂存块；最终提交先完成则返回已确认，保留会议与处理任务，绝不悄悄删除服务端会议。断网时保留本地取消待办和服务器状态未知提示，重连重试直至获得确定状态；重启不能重新上传该会议。删除设备录音不因远端离线而无限阻塞，设备上的删除墓碑和待办不依赖已删除音频文件。

### 首次可信时间与重启恢复

首次认证配网时，在用户核对一次性配对码并建立经认证、加密且防重放的 BLE 配置会话后，由配置工具提供 UTC 时间、时区、信任锚和设备凭据；设备验证消息与当前会话绑定、有效范围和格式，拒绝无认证、重放、明显不合理或回退到已保存可信时间下界之前的时间。时间源是配对电脑的时钟，必须检查电脑已同步且显示其时间供用户确认；配置工具自身时间若错误，设备不得声称已获得可靠时间。设备将校时来源、可信状态和时间下界持久化，时区只影响显示。建立 HTTPS 时仍正常验证证书链、主机名和有效期；**不能为了校时关闭有效期校验，也不能将未经验证的网络时间设为可信时间**。BLE 配对认证、防重放和时间合理性验证的具体机制须实现并通过安全测试，不以设想等同完成。

重启后若无法证明 RTC 连续计时且时间可信，则状态变为 `时间未校准`，暂停所有需要证书有效期判断的 HTTPS 上传并保留录音，提示用户重新通过受保护 BLE 通道校时；无法连接手机或电脑时保持待上传，不伪造时间或删除录音。校时成功且 HTTPS 完整验证通过后，可由已认证服务提供时间用于后续校正；校正不得篡改既有录音的原始时间及其可信标记。错误时间、有效期外证书、校时失败、远端证书过期等问题须分开显示并可恢复。确有硬件证据证明特定重启类型的时钟持续可信后，才可优化为免重新配对校时。

## 服务端（本地验证建议）

HTTP 底座选择 Zerone Agent Runtime；模型和架构边界见[服务端专项方案](../../2026-10-30-agent-runtime-service-design.md)。

第一阶段在本机启动服务，设备与服务在可互访网络。服务端认证设备、持久化录音块，校验后组装音频，并在返回最终确认前将音频、元数据和可恢复的 `待处理` 状态持久化。音频文件先持久化并原子发布；会议记录与待处理任务在同一数据库事务提交。最终确认以该持久记录为依据，不能只依赖内存队列。重启时扫描待处理或租约过期任务并幂等入队，处理阶段以会议 ID 和阶段为幂等键；允许重试但避免重复可见结果。状态分别记录上传、ASR、纪要及失败原因，处理中崩溃可恢复。确认后、入队前崩溃也必须可恢复。

**传输完整与会议完整分别定义。** 结束清单包含会议 ID、结束原因（用户结束、30 分钟上限、空间不足或断电中断）、预期块数、总长度、整体哈希和截断/中断标志。服务端只有在清单及全部预期块齐全且长度和哈希一致后，才认定“已保存音频传输完整”并确认、触发处理。用户结束不保证真实会议已完整；达到上限、空间不足或断电中断均为会议内容不完整。对已完整接收的截断或中断音频，可自动转写和生成纪要，但结果、状态和导出都须醒目标注原因与不完整；缺块、校验失败或缺少清单一律不得处理为完整或不完整纪要。

ASR/模型采用接口适配层；初版采用阶跃星辰 `stepaudio-2.5-asr`，服务端在完整接收后以 HTTP SSE 处理；真实服务配置和密钥通过安全配置提供，禁止写入设备固件或仓库。30 分钟不同位置合成标记样本覆盖开头、中间及结尾，真实会议识别与稳定性仍需验证；纪要模型初版选择 `step-3.7-flash`（单条合成样例 API 可用，尚未通过 runtime 和真实会议验证），服务通过安全配置注入凭据；仅有适配接口或模拟结果不算端到端纪要验收通过。网页或其他结果入口尚未确定；在决定前可用最小本地页面查看录音、状态、转写和纪要。会议纪要需区分讨论、结论、行动项；没有明确责任人或日期时标待确认。服务端记录的音频与文本需要访问控制及删除策略，具体保留期限待定。

## 验收和风险

1. 从首次 BLE 配对、配网、验证服务端证书和设备身份开始，离线录音并结束；恢复网络后自动上传，处理完成可查看转写和纪要。错误配对码、错误证书/主机名、无效或已撤销凭据均拒绝；测试本地与远端凭据重置及离线撤销待办：断网重置后确认旧凭据在服务端撤销前仍可能有效、界面持续提示；设备和工具重启后以管理员身份幂等重试，服务端确认后旧凭据拒绝；无管理权限、新设备凭据或配对码不能撤销旧凭据。
2. 重复块、乱序、断线、确认丢失、数据损坏和服务端重启不得导致提前删除或重复可见会议；缺块、哈希错误或无结束清单不得触发处理。完整接收的截断/中断录音可处理，纪要和导出必须显示不完整及原因。
3. 注入服务端崩溃：音频持久化前、音频发布后数据库提交前、待处理事务提交后确认前、确认后入队前、ASR/纪要执行期间分别重启。不得在未达到确认条件时让设备删除；已确认会议必须自动恢复处理并只产生一份可见结果。
4. 上传中启动新录音、短间隔反复切换并在暂停期间重启；验证不再发送新块、采集实际启动延迟、无丢帧、状态持久化及结束后上传恢复。延迟目标通过实机测量并确定；目标未定前不得声称体验达标。
5. 录音中断电后重启，可识别并上传已持久化部分且标记中断；测量尾部损失。接近容量或 30 分钟上限时提示并保存、标记截断；验证服务不可用时单条删除的二次确认、取消、成功回读与失败恢复，不能以不存在的蓝牙导出作为验收条件。
6. 故障注入删除与上传交错：删除前、意图持久化后、请求取消前后、服务端最终提交与取消竞争、确认丢失及本地清理中分别断电/重启。验证无未授权重复上传、无误删服务器已确认会议、状态未知提示准确、删除恢复幂等且回读空间；特别验证确认已提交但响应丢失时不显示“未上传”，提示服务器可能已保存。
7. 在首次配网及重启后模拟未校时、时钟严重偏差或回退、错误/重放的 BLE 时间、过期/尚未生效证书及错误主机名；验证不绕过 TLS、不上传或删除音频，成功重新校时后恢复上传。
8. 明确未校时、网络、存储、上传、ASR 和纪要各状态；录音、转写、纪要可追溯，密钥不进入源码或日志。真实 ASR 和纪要服务均完成才能标记端到端通过；分别报告主机测试、固件构建与实机结果。刷机前确认固件和目标，避免覆盖尚未导出的录音。

单次离线时长取决于分区、编码和剩余空间：已有 soundcore 实测约 47 分钟，不能作为新固件保证值。录音压缩、Wi-Fi 与 Flash 内存竞争、固件分区大小、Flash 磨损、远场收音、ASR 幻觉及会议内容隐私均需验证。30 分钟上限及存储余量仍需实机验证；部署、服务端保留期限和模型生产配置仍需确定。
