# 会议录音卡：SCR1 离线录音与自动上传设计

状态：评审修订，待复审。本文细化 [会议录音卡主设计](2026-10-29-meeting-recorder-design.md)，沿用其删除、配网与认证要求及服务端 [API](../../../server/API.md)。实现和设备验收尚未完成。

## 目标与选择

设备离线录音并在保存后通过 Wi-Fi 直传已保存的 SCR1；单次不超过 30 分钟，录音期间不上传。网络、服务或设备重启均不得导致未确认录音静默删除。服务端自动转录和生成纪要，截断会议显著标记。初版不做实时上传、手机中转、说话人识别或 60 分钟承诺。

用户选择原始 SCR1 直传：服务端已有解析能力，不要求设备额外生成 Ogg 和占用第二份存储。另一方案是设备转换 Ogg；它增加转换及临时空间，不适合当前存储余量。既有 soundcore 的手机导出 Wi-Fi SoftAP 协议不能替代本方案的 STA 和 HTTPS。

## 分区识别与初始化

挂载失败绝不自动格式化。首次可信状态由受控的出厂制备流程在设备交付前建立：在完成全分区擦除和核验后，向独立持久区域写入绑定设备身份、分区布局版本和初始化代次的防篡改出厂凭据；该凭据的实现、密钥管理和制备流程尚待落地及安全验证。固件只在凭据有效、尚未消费、相关历史状态一致且全分区逐字节为擦除态时，认定为可初始化的全新分区。仅有擦除态或 NVS 缺失不足以证明全新；旧设备 NVS 丢失、凭据缺失或校验失败、读错误、部分格式化、非擦除字节或状态矛盾均为未知/可能有录音，禁止自动格式化并提示用户通过受控恢复工具检查。当前设备没有已验证的出厂凭据，不能声称可自动区分全新与旧设备；首次制备和已有设备迁移须作为实现前置条件处理。

满足全新条件时屏幕提示初始化，用户按键确认后先持久化绑定分区和操作 ID 的初始化意图，再格式化。格式化与挂载、读写验证成功后原子持久化完成状态并消费凭据。重启时若意图存在且无法证明格式化完成，不再次自动格式化，而进入人工恢复；取消或写入意图失败绝不格式化。任何损坏分区擦除须另行设计并明确授权。

## 录音快照与数据格式

采用只读投影恢复，避免完整文件副本和原地截断：保留原始 `.dat` 不变，顺序扫描完整且有效的 20 ms Opus 帧，确定有效帧数和最后完整帧末尾；将恢复原因、有效范围、帧数与源文件标识原子持久化。无法证明扫描结果或持久化失败时保留原始文件并提示需要恢复；不删除或覆盖。当前 soundcore 的 `recover_file` 会改头、重建索引，且 `scan_catalog` 会删除无效或零帧文件，不能直接用于此方案，实施前必须替换并验证。

上传映射固定为 `scr1-projection-v1`：上传流长度为有效末尾偏移；从原始文件按绝对偏移读取，字节 24–71（第三方文件密钥和 nonce）替换为零；对于断电未结束文件，头部 20–23 用经验证的完整帧数的 32 位小端表示替换；其余字节原样保留。结束时间字段保持原值，不虚构中断时间；结束原因通过清单 `interrupted` 表达。正常结束文件使用同一规则，帧数保持原值；上传流不包含有效末尾之后的残留字节。映射版本、有效末尾、帧数、源身份和清单必须持久化，重启和任意分块读取严格按相同绝对偏移重建。整体哈希及每块哈希均针对投影后的上传流；服务器确认对应此流，而本地原文件在确认前保持不变。任何源变化、读错误或无法验证映射均停止上传并保留原文件。

投影只需有界内存和小型元数据预留，不需要整文件副本；预留空间以实际双槽元数据、文件系统写入放大和最坏故障注入测量确定，不能先承诺具体大小。剩余空间不足以安全写入元数据时保留原文件、显示“空间不足，无法恢复上传”，不修改源文件；用户可连接维护工具做只读导出和离线恢复，该工具及权限流程必须在实施中交付并验证，不能把目前尚不存在的工具当成已可操作。设备不得建议删除唯一副本来腾空间。

## 身份、清单与上传

每次录音在写入前生成并持久化唯一会议 ID（随机 UUID，使用设备随机源）；文件 ID 与会议 ID 映射在重启后不变，不使用时钟作为唯一性保障。持久元数据记录录音状态、结束原因、原始录音时间与可信标记、快照长度、整体 SHA-256、块大小和块数。`user`、`limit`、`storage`、`interrupted` 与服务端含义一致；未校准时间传 null/uncalibrated，不用上传时间冒充。

完成快照后自动入队。固定块边界及摘要必须跨重启不变；块大小在实现时以小于 256 KiB 的有界缓冲选定，并以真实 TLS 堆峰值、存储空间、延迟和服务端上限验证，不将服务器上限当设备缓冲需求。顺序创建会议、查询服务器块、逐块校验及上传、提交最终清单；一致的已确认块跳过，内容冲突或损坏按 API 修复规则处理。设备在确认响应丢失时查询或重试，不推断已保存。

收到 `committed` 后逐项核对会议 ID、块数、字节数、整体哈希、结束原因、录音时间和可信标记；任何差异、不完整响应、401/403、TLS 错误、超时或连接断开均保留录音。服务端 409 integrity 使用 repair-status 和原始哈希块修复；缺块或元数据损坏时停止自动删除并提示管理员恢复。其他永久错误可见并按有限退避重试，不通过重试掩盖错误。

## 录音优先、删除及恢复

按键只发事件；采集、持久化和上传各由工作任务处理。开始录音时阻止发起新上传请求，取消或有界等待在途请求退出，再启动采集；必须测量按键到实际采集延迟、丢帧和 TLS 内存峰值。任何无法保证采集的情况显示失败而非录音中。停止录音并完成持久化后恢复队列；关闭网络不影响采集。

每个会议串行化上传、确认、自动清理和手动删除。匹配确认后先原子持久化确认及删除意图，再停止读者并清理文件与索引，核对删除和空间，重启继续清理；失败保留可见状态。手动删除依主设计双重确认并记录墓碑和远端取消待办；即使本地音频已删除、断电或离线，也不得丢失待办或重新上传。取消与最终确认的竞态由服务端持久化终态决定；已确认服务端记录保留，不把设备删除当服务端删除。

元数据采用版本化、可检测撕裂的原子提交（双槽或经验证等效机制），保留足够的空间完成确认、删除及恢复；持久化失败时不推进状态或删除音频。原始文件、快照、元数据和服务端收据之间每一个崩溃点均须故障注入验证；不能仅依赖 RAM 状态。

## 配网、认证和时间

**2026-11-03 用户决策：Agent 全自动操作。** 配网、设备身份建立和首次校时不再要求设备按键、人工读取配对码或人工核对时间和证书。下述人工校时方案仅保留为历史决策，不再作为目标产品的交互要求。正式方案仍需完成 Agent 与设备的自动认证、可信时间及证书更新设计和验证；当前仅实现单设备受控测试，不等于正式安全方案已完成。设备现未开启安全启动和 Flash 加密，当前测试不能防御能改写固件或 Flash 的攻击者。此决策不构成自动擦除未知或损坏录音分区的授权。

**当前单设备原型的人工首次校时例外（用户确认）。** 设备已实测未启用安全启动和 Flash 加密，用户选择由人工核对并建立首次时间下界，明确接受它不能抵御可改写固件或 Flash 的攻击者。首次下界只在构建时明确配置并匹配该设备 eFuse MAC 时开放；默认空配置拒绝建立，MAC 仅用于限定原型范围，不是认证凭据或防篡改证据。配置工具校验 HTTPS 证书链、主机名和服务端时间，与本机时间比对；经 Security 2 会话传送当前 UTC 和 CA，设备先显示完整 CA 指纹和 UTC 并要求按键确认。如果时间下界缺失，设备另外显示“无已保存时间下界”，要求用户再次确认后才允许建立；NVS 读取错误、断连、超时和取消均不得允许首次建立。已有下界仍拒绝回退，重启不继承运行时可信状态。下界写入或后续配置持久化失败时不得启动上传；即使部分步骤已持久化，重试仍须重新配对和确认。该例外仅适用于首次时间下界，不是防篡改出厂凭据，也不授权格式化或自动擦除录音分区；全新分区初始化仍遵循上文要求。服务器时钟错误、电脑及服务器同时偏差、物理修改固件或 Flash 不在此原型能独立防护的范围内。

沿用主设计的安全边界：配套电脑工具通过认证加密、会话绑定且防重放的 BLE 配置通道，提供 Wi-Fi STA、服务端 HTTPS 地址、信任锚、独立设备凭据和首次可信时间。原设计要求用户核对一次性配对码，现已由上面的 Agent 自动操作决策取代；正式方案必须提供无需人工输入的设备认证，不得将固定配对码或设备 MAC 当作可信身份证明。管理员身份独立于设备凭据，重置时保留旧凭据标识和幂等撤销待办及未撤销警示。设备必须验证 TLS 链、主机名和有效期；未可信校时、重启后无法证明时钟连续、证书过期或配对未完成均暂停上传、保留录音。具体 BLE 安全协议、工具实现、时间下界和证书更新须在计划中确定并经过安全测试；当前受控单设备配网实测不能代表正式方案已完成。

## 验收

1. 只读全分区擦除态检测、旧分区/NVS 缺失/损坏/读错误、拒绝与确认初始化及断电中断；未知分区绝不格式化。已有参考固件关闭自动格式化，空白设备初始化仍待实现。
2. 完整 30 分钟离线录音、实际空间与上限、存储满、断电恢复；分别标记原因并验证帧完整和实际损失窗口；覆盖接近存满、元数据预留不足、原始文件保持不变和只读导出恢复。
3. 测投影版本、跨重启与任意偏移块重建、整体和块哈希、服务端解码及音频帧一致性、SCR1 头敏感字段处理，文件大小、块数量、堆峰值和按键到采集延迟均在设备实测；录音期间无上传且无采集丢帧。
4. 注入每块断网、确认丢失、服务重启、设备断电、重复上传、完整性损坏与修复、空间满和凭据过期；只有逐项匹配的持久确认后才能删除。
5. 注入手动删除和确认竞态、每步断电、取消离线待办、凭据重置和撤销；确保墓碑、提示和幂等恢复符合主设计。
6. 首次配网、配对码错误/重放、错误时间、重启失时、过期证书与设备重配；实机端到端验证服务端转录纪要及空间恢复。构建、模拟、服务端测试和设备测试分别报告。
