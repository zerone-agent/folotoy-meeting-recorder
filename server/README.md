# 会议录音服务（开发中）

此目录尚未完成安全审计或端到端验收，不可作为生产服务部署。

当前包括：转写和纪要版本历史、失败重试及管理端重试接口、模型请求超时；agent-runtime 2.8.2 HTTPS 宿主；独立会议路由；SQLite 音频分块与处理状态；StepFun SSE 适配器；租约防旧任务提交；初步纪要证据校验。`npm test` 运行本地测试。运行要求 Node 22.13+；`node:sqlite` 在当前运行环境提示实验性。

尚未完成：设备侧 BLE 认证配网与撤销待办、多人管理员身份、物理安全删除、完整故障注入、用户界面验收、真实会议内容经 agent-runtime 的质量验收、设备端上传协议协同与实机端到端测试。本地单管理员认证、撤销接口以及离线备份恢复工具已实现，具体限制见下文。SQLite WAL/备份可能保留已删除的数据，当前删除不能承诺彻底抹除；纪要 agent 已关闭 SDK 会话持久化及文件快照，但仍需核查其他日志和外部供应商数据。勿放真实录音或凭据到未审计环境。

开发启动需要设置 `MEETING_ADMIN_TOKEN`（至少 7 个非空白字符）、`ZERONE_AGENT_HTTP_API_KEY`（至少 32 个非空白字符，且与管理员令牌不同）、`STEPFUN_API_KEY`、`MEETING_TLS_CERT` 和 `MEETING_TLS_KEY`。默认仅监听 127.0.0.1:3443。请自行准备带正确主机名的证书；不要关闭证书验证。运行 `npm start`。设备协议采用版本 1（详见 API.md）；配对机制仍待设备端联调。

处理请求默认最多等待 10 分钟，超时后记录失败并按照重试策略重新调度；已丢失租约的晚到结果不会发布。重新转写保留历史版本并清除当前结果，直到新版本生成。SQLite 升级时会回填旧版已有的转写和纪要版本。

开发版接口见 [API.md](API.md)。`MEETING_MINUTES_MODEL` 可覆盖默认 `step-3.7-flash`。长逐字稿按原始片段分批，逐批核验原文引用并拼接结果；它不会自动消除跨批重复或推断跨批上下文，质量仍需真实会议评估。

离线恢复工具及其前提见 [BACKUP.md](BACKUP.md)。必须保留恢复切换前最新的安全状态，不能在运行中直接替换 SQLite 数据库。

`MEETING_RETENTION_DAYS` 可显式设置正整数天数；未设置时不自动删除。启用后只清理完成处理且完成时间超过该期限的会议，并保留删除墓碑；尚在上传、排队、处理或失败的会议不会自动清理，旧数据中没有完成时间的会议也会保留。重新转写会在新纪要完成时重新计算完成时间。管理员可通过 `GET /meeting-service/admin/settings` 查询当前配置。清理只针对当前库的逻辑内容，不包括供应商或历史备份。

本地管理员以独立的 `MEETING_ADMIN_TOKEN` 认证；`MEETING_ADMIN_ID` 可设置撤销事件的审计身份，默认 `local-admin`。这是单管理员本机部署方案，令牌须随机生成并安全保管，不能视为已完成多人身份管理。配套工具尚须实现持久化撤销待办并携带稳定的事件 ID。

管理员可通过 API 查看结构化转写和纪要，并将完整性校验通过的录音导出为 Ogg Opus。服务收到停止信号后不再领取新任务，主动取消当前模型调用并释放租约；供应商可能仍完成和计费，晚到结果不会发布。

可通过 `MEETING_STORAGE_LIMIT_BYTES` 设置服务端音频块的总逻辑字节上限；未设置时不限制。上限覆盖所有设备和未完成上传，达到时返回 HTTP 507；设备应保留录音并稍后重试。此配置不包括数据库索引、WAL、备份或其他文件，不是磁盘配额，实际部署还须预留磁盘空间并监控。

对外 HTTPS 监听器只允许 `/meeting-service` 业务路径，Runtime 内置 `/v1/*` 仅供进程内部使用；对外处理请求最多并发 64 个，超出返回 429，停机时返回 503。该限制是单进程并发保护，并非按客户端限速；如果开放到不可信网络，仍需在可信反向代理处部署限流、连接超时和网络访问控制。所有会议业务响应均禁止缓存。

本机启动后，可在浏览器打开 `https://localhost:3443/meeting-service/ui`，输入管理员令牌后查看会议、转写和纪要，下载录音，重试失败任务或确认删除服务端会议。验证成功后，页面将管理员令牌缓存于当前浏览器，7 天后过期；刷新页面会恢复未过期的令牌。浏览器需信任服务证书并且证书主机名匹配。已用真实浏览器和本地模拟数据检查待清理提示、会议列表和详情显示；完整交互、移动端和无障碍验收仍未完成。

长转写分批的有效结果会临时保存在数据库中，带转写版本、模型标识和实际提示内容的哈希；处理失败或重启后可复用已完成的批次。结果提交、重新转写和会议删除时会清理这些中间结果。模型调用仍可能在服务崩溃前已计费而结果未保存，不能保证外部调用恰好一次。

真实服务验证脚本：设置 `STEPFUN_API_KEY` 后，在 `server/` 目录运行 `node src/live-workflow.mjs ../test-audio/distance-03.opus`。脚本会将所选录音发送给 StepFun，调用 ASR 和纪要模型，可能产生费用；该示例的字符错误率以此前的 0.3 米标准朗读文本为参考，其他录音的这个指标不适用。它只输出指标和计数，不打印密钥或逐字稿，结束后删除临时数据库；异常终止时应检查系统临时目录是否残留 `meeting-live-*`。模型供应商及其日志的处理不由本脚本控制。

服务启动要求 `MEETING_DATA_DIR` 及已有数据库文件和 SQLite 附属文件由当前用户持有，且不允许组或其他用户访问；进程以 `umask 077` 创建新文件。若已有目录权限不符合要求，启动会报错，需要管理员确认后修正。权限位检查不能替代对文件系统 ACL、备份和主机安全的检查。

2026-10-30：此前授权的 0.3 米短录音已通过本服务、真实 StepFun ASR 与 agent-runtime 纪要链路；参考文本字符错误率约 7.3%。引用位置通过校验，但语义准确性和真实会议表现尚未验收。

启动时会验证 TLS 证书的有效期及其与私钥的匹配，并要求端口为 1–65535 的整数。只有 HTTPS 端口成功监听后才启动后台队列；若端口被占用，服务退出且不会开始处理录音。客户端仍必须验证证书链和主机名，启动检查不代替客户端验证。

关闭服务时，停止接受新业务请求，并等待现有连接最多 10 秒；超时后断开连接、中止未完成请求并等待业务处理退出，再关闭数据库。设备必须将连接中断或超时视为结果未知，重新查询并核对完整清单后才能删除本地副本。服务器的请求头、请求和空闲连接分别设有 15 秒、30 秒和 5 秒超时；部署在反向代理后仍需配置代理侧超时与限流。

对已有的三段不同合成标记样本，可在上面的真实服务验证命令中将音频路径替换为该样本并追加 `--distinct-markers`。输出的三个布尔值和顺序标志用于判断标记是否出现；标记缺失或顺序不符时脚本返回失败状态和非零退出码；成功也不保证纪要语义正确。
