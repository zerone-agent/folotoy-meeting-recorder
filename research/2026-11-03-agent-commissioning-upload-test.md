# Agent 自动配网与上传实机测试（2026-11-03）

设备：AI Passport ESP32-C3，8 MB Flash；服务端：`meeting-recorder.zerone.life` 的 `v0.1.2`。本次使用针对该设备的测试构建，由 Agent 自动进入 BLE 配网、提交 Wi-Fi 和服务端凭据、建立首次时间下界，再通过 Wi-Fi 上传；未擦除录音或 NVS 分区。该测试构建的自动确认与固定配对码只适用于指定设备，不能证明正式产品的身份认证或抗物理篡改能力。

结果：设备成功连接 2.4 GHz Wi-Fi；在网络波动后恢复上传，将约 20 秒、36,640 字节的测试录音传至服务端并收到确认。旧版服务缺少分块窗口接口，设备通过旧接口校验已接收分块并续传；实际测试跨固件重启和多次网络请求失败，但不是全面故障注入验收。

电脑合成的标准文本是“今天是会议测试。决定周五完成第一版。小王负责整理需求，小李负责测试。下周一检查交付结果。”服务端转录为“今天是会议测试，决定周五完成第一版，小王负责整理需求，小李负责测试，下”。纪要正确提取周五、需求和测试分工，并将末尾不完整内容标记为待核对；最后一句未被完整识别，不能据此认定转录准确率达标或完整内容未丢失。录音时间因采集时可信时钟尚未建立而标记为 `uncalibrated`，没有使用上传时间替代。

实测问题与处理：初始构建因内存不足导致按键任务和 BLE 广播失败；调整配网缓冲生命周期后恢复。Security 2 握手内存不足，ESP-IDF 5.5.3 失败清理中出现重复释放并重启；释放空闲编码资源并对固定版本清理路径修补。设备 Wi-Fi 从纯 5 GHz 改为 2.4 GHz 后连接成功。TLS 握手内存不足后将空闲录音栈改为按需释放。一次测试时电脑扬声器静音，录音为空；复测后恢复了电脑原静音状态。

限制：9 条旧参考固件录音缺少当前会议身份元数据，快照准备失败并保留，尚无经过验证的迁移方案；其他较短测试录音已上传，但 ASR 返回空文本。自动配网原型重启后仍依赖电脑端重新建立可信时间，不是脱离 Agent 的完整重启恢复。30 分钟连续录音、近满断电恢复、录音中抢占上传、网络故障交错、长期稳定性及标准样本准确率仍需实机验收。当前设计与代码尚未提交或发布。

## 在线录音与空文件恢复补测

在设备已获得 Wi-Fi IP、上传工作器运行时，由设备专用测试开关自动请求录音：设备先取消当前上传并停止 Wi-Fi，约 0.3 秒后开始采集；录得 524 帧并保存，随后重新连接 Wi-Fi。服务端后来持久确认了该录音；由于测试时没有播放语音，ASR 返回 `asr_empty`。这是一次受控样本，不代表反复切换、各上传阶段的抢占或最长启动延迟已全部验收。

诊断期间发现一条 96 字节、仅有 SCR1 头部的中断录音；只读分区镜像和 NVS 元数据校验表明它有合法持久身份、无结束意图，且没有音频帧。固件现在保留并显示这类记录，跳过上传，同时允许其他录音继续；身份缺失或内容异常仍禁止将其视作可安全隔离的空记录。主机测试覆盖已验证空记录与身份缺失两种情况。自动触发录音的设备专用测试开关已关闭，设备恢复普通测试固件并重新联网。

## 音频启动与停止故障保护

音频驱动现在在录音文件创建前完成资源分配、codec 唤醒和采样格式配置；准备失败时不创建文件，也不报告录音开始。停止采集超时时，核心保留尚未关闭的文件和录音所有权，不启动上传，允许后续重试；保存失败时不再显示“已保存”。主机测试直接运行音频模块，模拟唤醒、格式设置、休眠失败和停止超时，以及故障后的恢复。

实机在在线状态下重测：设备先暂停上传并停止 Wi-Fi，codec 成功打开后创建文件，采集 517 帧并保存，再恢复无线连接。自动录音测试开关随后已关闭，普通测试固件构建及刷写成功，设备重新获得 Wi-Fi IP。设备实测没有注入 codec 硬件故障或强制停止超时；这些异常的实机效果仍未验证。

## 写入队列与删除状态的主机测试

写入队列现在在入队前登记待处理帧，关闭录音前有界等待所有已接受帧完成写入；帧丢失时记录为中断，而不是报告完整会议。写入任务的停止请求通过可重试的序列信号传递，避免队列满时丢失停止通知。这些改动通过了主机测试和 ESP-IDF 5.5.3 测试配置构建，尚未在设备上验证。

手动删除的双槽状态记录及 NVS 适配器增加了 CRC、状态单调性和录音身份绑定检查；测试覆盖写入失败、提交结果不确定、损坏数据和跨录音身份。**这只是状态存储基础，尚未接入设备删除操作、上传互斥或服务端取消，不能作为手动删除已完成的证据。**

关闭自动长录音测试开关后的设备专用配置已通过 ESP-IDF 5.5.3 构建和分区布局检查，应用镜像 2,034,592 字节，factory 分区 3,145,728 字节；构建归档为 `62c8f9abedfa3dda2de1e9d208a50079f5c8bbe999ab0eb0720d9f621224e4a0`。该构建仍包含单设备 Agent 配网原型，尚未刷写或完成实机验收。

## 30 分钟采集与保存失败

设备专用测试构建 `622876dd8ef982a7ccaeb6f0bae1214299605686d885f5f40662a00afab0c4bd` 在 2026-11-03 采集日志显示 90,003 帧、平均 35 字节每帧；这只证明采集端输出，不证明全部帧已保存。结束时 `sc_core` 两次触发任务看门狗，随后 LittleFS 报 `No more free space`，`sc_store` 报保存失败并停止存储操作，设备提示文件已保留。之后自动配网报网络启动失败；未取得上传确认。测试未成功，原始文件是否完整、可恢复的帧数和空间占用待只读检查。

用该构建的 ELF 对看门狗时的 PC 和返回地址进行符号化，落在 LittleFS `lfs_bd_read` / `lfs_file_flushedread` 和 `lfs_bd_prog` / `lfs_file_flushedwrite`。当前 `sc_store_end` 在完成同步和结束意图持久化后回写大文件开头的 96 字节头部；LittleFS 写入放大是故障的主要排查方向，但仅凭 PC 采样不能证明全部因果。结束意图本身不证明文件完整，不应仅因为它存在就把未封口文件标为完整。需要设计可验证的持久结束证明并以只读投影生成封口头，再通过近满空间、断电和 30 分钟实机测试确认。

进一步在该分区镜像的独立副本上使用相同 LittleFS 参数重放旧封口操作：对 3,266,028 字节录音的前 96 字节写入返回 96，但 `lfs_file_sync` 报 `No more free space` 并返回 `-28`。这在相同分区数据的副本上复现了大文件头部回写无法同步；实验未修改设备或只读备份。新版避免该回写，但仍需在设备近满空间下验收。

随后通过 USB 只读获取录音分区和 NVS 镜像，在电脑上以只读 LittleFS 导出原始文件。测试文件 `1793586284.dat` 为 3,266,028 字节；SCR1 扫描得到 90,000 个完整 20 ms 帧（1,800.00 秒），无不完整尾帧，头部帧数字段仍为 `0xffffffff`（未封口）。这证明备份中有 30 分钟结构完整的压缩帧，不证明全部帧可解码、原会议内容无损或服务端已收到。原分区镜像 SHA-256 为 `60194d4e98db90195cb99ed336f858f1b18cb01bc2d03ed4fa030a94146b46ac`，录音文件 SHA-256 为 `b05327758762afe0cf4d08df201ddf59fa6a77f99a9f06319af09db90b2d376d`；镜像和文件仅保存在本机私有临时目录。

故障时 NVS 镜像中的该录音记录 CRC 有效，结束意图是达到时长上限（2）；但文件头仍开放，说明结束意图已持久化仍可能随后保存失败。新版缺少独立结束证明时将开放头文件按 `interrupted` 恢复，而不是仅凭意图标记为正常完成。

在私有副本上按投影规则写入 90,000 帧并清零敏感头字段后，服务端 SCR1 结构验证通过、转换为 Ogg Opus，FFmpeg `-xerror` 完整解码至空输出且退出码为 0。这进一步验证该副本的压缩数据可解码，不代表实际设备已上传或会议内容完整。

对同一原始文件使用固件 C 投影实现倒序读取 798 个块，重组结果与独立按规则投影的字节逐字节一致，SHA-256 为 `c613493601887866556b75b70a060a51062f420e1c3a89725d406c76f96d7a9a`。这验证本地主机上的实际长文件随机访问结果，不证明设备上的跨重启读写或 Wi-Fi 传输。

使用同一投影字节流和本地内存数据库的服务端路由，按 4,096 字节分成 798 块：缺少最后一块时提交返回 409；补齐后按 `interrupted` 提交获得完整匹配的确认，再次提交返回同一清单。此实验只在本机内存中执行，不经过设备 Wi-Fi 或线上服务，不证明实际断网续传或数据库跨进程持久性。

另用本地磁盘 SQLite 文件测试同一长录音：上传 400 块后关闭并重新打开数据库，400 块仍可查询；补齐至 798 块并确认后再次关闭、重开数据库，查询与重复确认均返回原清单。测试在同一个本地进程中重新构建服务路由和存储实例，验证数据库重开行为，不等同于设备网络断流、真实服务进程故障或线上验收。

进一步使用三个独立本地 Node 进程、同一临时 SQLite 文件复测：第一个进程保存 400 块后退出，第二个进程读取这 400 块、补齐并确认，第三个进程恢复确认并幂等重试成功。调用仍是进程内路由请求，没有建立真实 HTTP 服务或模拟设备网络断流。
